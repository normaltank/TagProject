# Issue tracker: GitHub

仓库：https://github.com/normaltank/TagProject
需求、规格和任务统一记录为此仓库的 GitHub Issues。

- 优先使用可用的 GitHub 工具；gh 可用时也可使用。
- 发布规格或任务：创建 Issue。
- 读取任务：读取正文、标签和评论；更新前核对最新状态。
- 多行正文使用结构化工具参数；使用 gh 时通过 UTF-8 文件和 --body-file 提交。
- 状态标签见 [triage-labels](triage-labels.md)；执行阶段与关闭门槛按 [workflow](workflow.md)。
- 拆分任务优先使用子 Issue；不可用时以父任务清单和 Part of #编号关联。
- 依赖优先使用原生依赖关系；不可用时记录 Blocked by: #编号。
- 规格作为父 Issue，实施票作为子 Issue；认领、回答及完成证据留在对应任务。拆票时保留规格正文与开启状态，不以派工评论代替任务。
- 公开内容采用脱敏说明；原始教师资料、运行明细和密钥留在本机。

PRs as a request surface: no.

## 任务评论记录格式

在对应任务追加记录；阶段属于评论字段，仍沿用五个 triage 标签。以下只规定记录内容，进入与完成条件以 workflow 为准。

- **认领／派工：** 阶段；采用逐票 implement 或完整 implement-spec；来源规格／任务；范围及排除项；逐项验收入口；base SHA；依赖及就绪证据；执行者、文件归属和主 Agent；资源／API 授权边界。
- **执行交付：** 阶段；base／待审 head；逐验收项的结果→证据位置；适用检查结果；改动范围；未完成项、限制及实际用量。完整 implement-spec 另记 merger、集成提交与依赖产物就绪证据，保留待整体审查状态。
- **审查／复核：** 共同 base／head、三点 diff 命令及提交列表；Standards 和 Spec 各自的审查者、结论、发现及限制；修正后 head、复核范围与各轴最终结论。
- **接管／变更／受阻：** 原因；已停止的写入／运行及核实结果；已完成和待办边界；已用与未知请求状态；新责任人／文件归属；范围或授权变化；当前阶段及恢复条件。
- **归档／关闭：** 最终 head 与提交链接；逐验收项证据；两轴最终结论入口；同步与归档结果；主 Agent 验收结论及关闭理由。缺项记录为待办，按 workflow 保持相应未完成阶段。

已确认规格发布后，仓库只保留入口；本地草稿冻结为历史，不作为第二份任务状态。
