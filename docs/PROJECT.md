## 用户要求：业务对象与成功方向

教师标注描述其有证据支持的研究专长；待审稿件标注描述本次研究内容。两者共用同一正式概念集合、定义和稳定概念 ID，从而能比较专业方向。两类对象的识别、聚合、阈值和模型可不同。

“论文分类”在本业务指待审稿件分类。教师简介中的代表作、项目可作为专长证据；标题补查摘要、关键词或全文仅作为成本收益实验，不设为默认步骤。偶然提及、授课、导航栏或单篇论文的主题不直接等同于持续专长；文本未提及也不代表教师没有该方向。

系统长期目标是可批量运行、保留原始证据、允许人工审核、持续改进。当前重点为识别与词库管理。专业方向匹配仅作下游验证；完整审稿推荐、邀审、利益冲突检测、期刊管理和采集链路重写不在本阶段范围。

## 用户要求：三个核心问题

1. **表达能力**：区分已有概念但未识别、定义模糊／边界重叠／层级问题、同义异名、颗粒度不足、只需组合表达或保留原文。教师与稿件都参与表达需求评估。学科层级、主题、方法、对象、应用等组织方式需要论证，不预先定为多轴架构。
2. **同库赋标**：支持细粒度、多标签、跨学科与原文证据。区分充分支持、线索不足、资料不足、词库表达不足、模型不能可靠判断，允许拒判及复核。
3. **受控演进**：模型提取词、聚类和主题只能成为候选。至少提供已有概念别名、已有概念组合、原始描述／证据、经审核新正式概念四种去向。新概念要有定义、边界、真实资料依据和增量区分价值；低频专家提案可进入审核，不用任意总数上限代替治理。

词库需要同义归并、上下位、跨学科关联、合并、拆分、废弃、版本发布与历史迁移。概念含义变化后须重新核验旧结果，单独改名称不解决语义迁移。

## 用户要求：多语言

中文、外文和混写是正式输入；外文不限英语。先核实语种、长度、混写与来源；文字脚本、网页域名和真正语种分别报告。

不同语种的规范名、别名、缩写关联同一概念 ID；保留原文。翻译若使用，要记录译文、来源、版本和原文对应位置；不预设全量翻译为中文，也不预设多语言模型覆盖所有语种。处理一词多义、缩写歧义和学科差异，不因语言不同重复建概念。

评测覆盖中文、主要实际外语、混写和外文稿件—中文教师资料。教师、稿件、重复／翻译版本按实体分组，防止跨集合泄漏。

## 用户要求：路线、评测与第一阶段交付

技术路线保持开放，比较规则／传统分类、编码器、标签定义检索重排、LLM 直接分类或先提取再映射、弱监督／主动学习／Teacher–Student等。训练是否必要以成本和独立评测证明；Teacher–Student 不是默认主架构，须处理 Teacher 偏差、伪标签筛选和错误传播。

第一阶段按盘点、读数据、建立基线、比较至少三种方案、设计区分问题来源的实验、记录结论与下一步推进。允许必要本地审计脚本；全量标注、长训练、部署、正式词库迁移尚未获授权。

实验至少含独立人工答案、师稿分别评测及共享语义、各层级与具体内容覆盖、多标签／跨学科／长尾／长文本／多语言／证据不足、误标／漏标／证据支持／人工成本、词库变更影响与全量成本假设。优先原词库／优化词库 × 基线方法／改进方法对照；公开项目指标不能当成本项目效果。

## 设计建议：下一阶段输出契约（尚未实施）

建议将来源记录、内容单元、概念和赋标结果分开：

- 来源记录：对象类型 teacher/manuscript、内部实体 ID、来源文件／sheet／行／字段、原文摘要哈希、采集／文档时间、可用性状态；原文按权限保留。
- 内容单元：原文证据区间（字符偏移起点含、终点不含）、语言及判断来源、段落角色、与对象的关系、时间和证据来源。正文解析／翻译时保留到原文的映射。
- 正式概念：稳定 ID、版本、状态、各语种规范名与别名、定义／范围说明、上下位与关联、历史变更。当前来源行 ID 与审计 occurrence ID 仅用于追溯，尚不充当已审核概念 ID。
- 赋标结果：对象 ID＋概念 ID＋词库版本、证据区间与证据角色、教师持续性／稿件本次主题判断、模型／规则／提示词版本、分数及校准版本、决策状态与原因、审核与修订历史。

判断建议分离“资料是否足够”“概念是否能表达”“该标签证据是否成立”“模型是否确定”。同一对象可同时有充分支持标签和待复核标签，不能用一个全局强制标签掩盖差异。
